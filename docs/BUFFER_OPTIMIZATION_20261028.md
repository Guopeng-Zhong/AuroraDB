# 扫描准入与页对象所有权优化（2026-10-28）

## 实现变更

保留原6000行数据、插入顺序、字段、四类负载、种子及计时边界。未修改用户数据库或磁盘页格式，未覆盖原历史结果。

1. 新解码页没有调用者别名，可以直接交给缓存；缓存持有时，返回调用者的仍是独立副本。此项同时用于LRU与预测策略。
2. 预测策略增加扫描准入快速路径：缓存已满、刚读取的页被标记为扫描页、LRU驻留页具有更强的点访问历史、且没有活动扫描明确需要该新页时，不让该扫描页污染缓存。无法确认时仍走采样淘汰。
3. 若新解码页最终未被缓存保留，缓存和事务都不持有它，直接将该对象所有权交给调用者，避免复制不共享的对象。
4. 提交发布、事务暂存和缓存命中仍保留隔离复制。CRC验证仍在训练、准入和返回之前执行。

这是一项策略行为变更，不再声称与旧版本的每次淘汰相同。不是预取，也不是修改原实验负载。缓冲池的cache_evictions和predictive_evictions将准入拒绝视为新页立即淘汰的等价决策；另用predictive_admission_bypasses单独记录此类情况，未发生缓存驻留页移除。disk_reads仍为实际文件读页计数。

## 正确性

`python -m unittest discover -s tests -t . -v`

测量阶段260项测试全部通过。基于远端最新main整合后，完整264项测试再次全部通过，日志见 `docs/buffer_optimization_20261028/integrated_revision_tests.txt`。新增验证：解码后缓存页的嵌套读结果隔离；扫描准入拒绝后的结果隔离；另一活动扫描的已知后继页不可被快速拒绝。保留已有WAL、回滚、CRC与索引测试。

## 原基准完整实验

6000行；容量8/24/64；采样1/4/8/32；四类负载；每配置3轮；180次运行、48组对照。所有查询结果一致，35组总耗时低于同版LRU，13组更高。热点夹大扫描12组与热点迁移12组全部更快；重复范围11组更快1组更慢；纯扫描12组全部更慢（约7.58%—33.84%）。全部网格结果保留，不据此声称普遍加速。

预先选定的热点夹扫描、24页、采样8配置：

|指标|同版LRU|新预测策略|变化|
|---|---:|---:|---:|
|文件读页|3769|3584|减少4.91%|
|总耗时三轮均值|320.816ms|239.595ms|减少25.32%|
|每轮操作P95的均值|0.30774ms|0.29351ms|减少4.63%|

每轮预测策略均有3533次扫描页准入拒绝。文件读页改善和减少不必要的页复制共同贡献收益，不应将所有耗时改善归因于物理磁盘IO。

## 独立同场五轮确认

每轮随机安排旧LRU、旧预测、新LRU、新预测。公平对照为同版新LRU与新预测，双方都使用解码页所有权优化。

新LRU均值326.994ms，新预测249.464ms，降低23.71%。
P95均值分别0.35362ms、0.31030ms。原始五轮和最终确认五轮记录分别保留，不混合不同阶段数据。早期只优化缓存接管、未优化返回所有权的试验仍有总耗时退化，见paired_benchmark.log。

## 跨批次耗时的解释

10月27日旧代码完整实验中LRU约699.32ms、预测约711.96ms；10月28日最终同场五轮中，旧LRU约412.29ms、上一版预测约442.07ms，新LRU约326.99ms、新预测约249.46ms。基本相同的旧LRU也出现明显跨批次差异，因此不能将约712ms到约240ms的全部下降归因于代码。CPU调度、频率或宿主机负载等可能影响结果，但未记录这些监控信息，不能准确归因。

性能结论以同一批次、同版新LRU与新预测的对照为准，完整三轮和独立五轮分别报告。
