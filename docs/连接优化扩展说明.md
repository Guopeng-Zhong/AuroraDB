# 连接优化扩展说明

本次扩展使优化不再局限于显式等值 JOIN 的多表顺序搜索，同时保持原来的默认启发式模式和 PPT 演示接口。

## 已实现的范围

| 查询形式 | 优化方式 | 边界 |
| --- | --- | --- |
| `INNER JOIN ... ON` | 连接条件规范化、单表过滤、访问路径选择；符合要求时动态规划重排 | 顺序搜索限 3–6 表、连通等值内连接、左深计划 |
| 逗号连接、`CROSS JOIN + WHERE` | 将纯内连接中的跨表 WHERE 条件归入连接条件，复用同一套规划 | 不拆分 OR；没有连接条件时仍是真实笛卡尔积 |
| 两表连接、顺序搜索回退的查询 | 自适应模式也能提前过滤右输入，并比较其索引与表扫描路径 | 两表不启动多表顺序搜索；模型不可用时使用原有规则 |
| 非等值连接 | 对直接列的 `< / <= / > / >=` 条件使用 RangeJoin | 不参与当前动态规划重排；复杂表达式等保留嵌套循环 |
| LEFT JOIN | 右表独立 ON 条件可提前过滤、使用索引；直接范围条件可用 RangeJoin | 不改变外连接顺序；可空侧 WHERE 条件仍在连接后检查 |

子查询、USING/NATURAL、RIGHT/FULL JOIN 仍未实现。不能把此次扩展描述为支持所有 SQL 连接形式。

## 具体实现

- [sql.py](../auroradb/sql.py)：识别逗号与 CROSS JOIN，保存连接写法及逗号分组作用域。显式 JOIN 的 ON 不能引用前一逗号组的表。
- [join_planning.py](../auroradb/join_planning.py)：在名称绑定后规范化纯内连接，将顶层 AND 中的跨表条件放到最早可计算的连接前缀，将单表 ON 条件转为过滤；存在外连接时不跨越该屏障改写。另提供安全输入过滤和范围连接键识别。
- [join_optimizer.py](../auroradb/join_optimizer.py)：允许原 SQL 的某个前缀暂时没有连接边、但完整连接图连通的查询进入搜索。原顺序成本计分遇到无连接边的前缀时按笛卡尔积规模计分；新候选仍只沿真实连接边扩展。
- [engine.py](../auroradb/engine.py)：两表和回退路径接入右表访问路径与过滤。RangeJoin 排序右输入，对左行二分定位候选区间，再计算完整 ON；保留重复值和 NULL 语义，LEFT JOIN 无匹配时仍补空。非哈希连接的耗时不写入哈希连接成本模型。
- [optimizer.py](../auroradb/optimizer.py)：序列化时保留逗号和 CROSS 写法，保证可信改写往返解析仍保留作用域与结构。

范围连接只选取一个直接范围边界缩小候选，其他 ON 条件全部复查。其主要工作量为右侧排序、每个左行二分和候选检查，约为 `O(R log R + L log R + K)`，另加结果物化；K 是需要检查完整 ON 的候选数。排序有开销，并非所有范围查询都会更快。没有 ORDER BY 时，合法的输出顺序可能随物理算法变化。

## 可在默认教学库使用的查询

通过工作台“研究实验”切换到 adaptive；采集统计后可进一步使用统计估计与多表顺序搜索。以下查询只读已有数据。

```sql
-- 隐式连接：与等价的 INNER JOIN 写法返回相同记录集合
SELECT s.id, e.course_id
FROM students s, enrollments e
WHERE s.id = e.student_id AND e.score >= 90;

-- CROSS + WHERE：连接条件进入连接处理，而非必须先物化完整笛卡尔积
SELECT s.id, e.course_id
FROM students s CROSS JOIN enrollments e
WHERE s.id = e.student_id AND e.score >= 90;

-- 范围连接：查看 RangeJoin 计划与候选检查次数
EXPLAIN ANALYZE
SELECT a.id, b.id
FROM students a JOIN students b ON a.gpa < b.gpa;

-- LEFT JOIN：找没有满足高分条件选课记录的学生
-- e.id IS NULL 必须在补空之后检查，不能随意下推
SELECT s.id
FROM students s LEFT JOIN enrollments e
  ON s.id = e.student_id AND e.score >= 90
WHERE e.id IS NULL;
```

## 验证记录

2026-10-28，在 Windows、Python 3.13.9 下完成：

- 全量 `python -m unittest discover -s tests -v`：279 项测试通过，涵盖存储、WAL/故障恢复、索引、SQL、事务、HTTP、AI 与研究模块。
- 新增 `tests/test_join_forms.py` 15 项测试：含 120 条固定种子的随机查询，各在两种模式下与 SQLite 核对结果多重集合；另覆盖 NULL、重复值、空表、数值类型兼容、布尔范围、外连接链、索引过滤、解析和序列化。
- 三表隐式、CROSS、WHERE 等值和星形连接均验证可复用动态规划；EXPLAIN 不执行记录，实际查询每张表只读取一次。
- 100×100 条范围连接测试：候选 ON 检查从 10,000 次降到 4,950 次，结果一致。该计数不包含排序和二分内部比较，不能直接等同于耗时改善比例。
- 前端研究功能 smoke 通过：165 个 HTML ID、预算、CSRF、错误隔离、并发查询、PPT 演示及现有主题切换。旧测试脚本原先禁止所有浏览器持久化，与既有主题偏好保存冲突，已仅允许固定 `aurora-theme` 偏好并补齐 DOM 模拟；生产布局和主题功能未改动。
- `tools/check_macos.py` 的资源、中文/空格路径、文件锁、HTTP、PPT 演示、事务隔离和重开检查通过。当前主机不是 macOS，报告中的 `native_macos_verified` 仍为 false，需要在目标 Mac 上运行同一检查才能确认原生环境。

现有 PPT 用例仍返回 100 行，默认策略与自适应策略分别为 20,000、200 次连接候选比较。该例证明整体规划流程的效果，不能单独证明学习模型的增量收益。

详细测试日志保存在本机 `.build/join-extension-full-tests.txt`，兼容性报告为 `.build/macos-compatibility.json`。这些检查提供已覆盖场景的回归证据，不等于所有未知输入的正确性证明。
